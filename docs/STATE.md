## 04.01 — App runtime (2026-10-05)

Done:

- `compose/app`: `srot-vault-agent` (AppRole auto-auth, token watchdog from
  vault_reference, sink in the `agent-token` volume, healthcheck is a real
  token lookup), `srot-api` (read-only root, uid 1000, `NODE_EXTRA_CA_CERTS`),
  `srot-web` (unprivileged nginx on a read-only root, lazy upstream through
  Podman DNS, CSP), one-shot `volume-init` for the sink's ownership.
- `make app-credentials`: role-id from Terraform output, secret-id with the
  root token, kept while Vault accepts it. Never in Terraform state.
- API: `config.js` (names from env), `vault.js` (token file read per call,
  Vault's error text verbatim), `pulse.js`, `GET /api/platform` (seal and
  vault health, postgres reachability, the agent identity's TTL and
  policies — no token). `dotenv` removed.
- Web: `src/api.js` (same origin by default), Vite proxies `/api` in dev.
- Make: app-credentials, app-build, app-up, app-down, app-rebuild, open, up,
  down; `verify` section `app` drives all three lanes over HTTP.

Validated: 45/45 `make verify`; agent restart; `make down && make up`.

Learned:

- `podman build` defaults to the OCI image format, which drops
  `HEALTHCHECK`. Build with `--format docker`.
- The nginx image's envsubst step does not create its output directory;
  render straight into `/tmp`.
- An `add_header` inside a `location` drops every server-level header,
  including CSP. Cache headers use `expires` instead.
- Node as PID 1 ignores SIGTERM; the API now closes its server on SIGTERM.

Learned:

- Without the mount tune the 90-day secret-id would have been capped at
  vault-1's 24h `max_lease_ttl` — Durin's 7-day bug, here in a day. `verify`
  now checks the secret-id's real lifetime.

  agent's auto-auth `max_backoff = 30s` (default 5 minutes) so a recovered
  secret-id is used promptly.
- `doctor | grep -q` under `pipefail` fails whenever doctor finds the problem
  it is meant to find (exit 1). Capture output, then grep.
- The rotator-login probes in status/recover/doctor revoke their token, so
  they do not leave one 5-minute token behind per call.

## 08.01 — The seal plane heals itself too (2026-10-05)

Done:

- Rotator and agent entrypoint moved to `compose/common/` and shared by both
  planes (no copies).
- `terraform/vault-seal` on vault-s: `auth/approle` tuned to 2160h (vault-s's
  768h maximum would otherwise cap the 90-day secret-id), role
  `seal-autounseal` (`autounseal` policy, periodic 24h tokens, 90-day
  secret-id, CIDR-bound), role and policy `seal-rotator`. The bootstrap
  keeps owning transit, the key, the policy and the fallback token.
- `srot-seal-rotator`, `srot-seal-agent`, volume `seal-token` shared with
  compose/vault (`ensure_seal_token_volume`). `vault-server.sh` prefers the
  sink token, verified against vault-s; falls back to the bootstrap file only
  on an explicit rejection.
- `scripts/seal-up.sh` (vault-s → unseal → renew fallback → rotator + agent →
  wait), `seal-token-status.sh` (hash-compares the token vault-1's PID 1
  holds with the sink and the fallback; never prints it), `rotator-bootstrap`
  for both planes, `agents-status`/`agents-recover`/`rotate-now ROLE=` for
  both, `make bootstrap` ends with vault-1 on the agent's token.
- `verify` +4 (seal rotator and agent, vault-1 on the agent token, 90-day
  seal secret-id), `doctor` seal checks, `rotation-test` case 5.

Learned:

- Moving a bind-mounted file breaks the container that mounts it — not now,
  at its next restart. The API agent's watchdog exit during the test could
  not be followed by a restart ("cannot stat compose/app/agent/entrypoint.sh")
  and the API stayed down. `make doctor` now flags any `srot-` container
  whose bind-mount source no longer exists; `make up` recreates.
- The token in `/proc/1/environ` carries a newline the files do not; compare
  normalised hashes.
- The user switched `.env` to Vault Enterprise 2.1.1 mid-session; everything
  carried over unchanged (D1 override).
